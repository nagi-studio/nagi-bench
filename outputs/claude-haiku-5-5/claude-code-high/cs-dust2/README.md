# Dust Strike — 浏览器 3D 第一人称射击原型

基于 **React 18 + TypeScript + three.js** 的 Dust2 中路区域 5v5 对战原型。
地图、角色、武器全部由代码程序化生成，声音由 Web Audio 实时合成，**不使用任何外部模型 / 贴图 / 音频文件**。
寻路、状态机、物理、回合逻辑均为自研；第三方库只用 `three` / `react` / `react-dom`。

## 运行

```bash
npm install
npm run dev        # 打开 http://localhost:5173 ，点击“开始比赛”
npm run build      # tsc --noEmit + vite build
npm test           # 逻辑层单元测试 + 模拟对局测试（Node 22+）
```

## 地图

`src/game/map/layout.ts` 用字符矩阵描述 52×48 格（每格 2m）的俯视布局，是唯一的地图数据源：

| 字符 | 含义 |
| --- | --- |
| `#` | 墙（3.4m，不可穿越） |
| `x` / `l` | 箱子 / 矮墙（1m，可跳上箱子） |
| `D` | 中门门洞（旋转门，关闭时阻挡） |
| `A` / `B` | A 点 / B 点（炸弹点） |
| `T` / `C` | T 出生区 / CT 出生区 |

区域与走位（北 = 画面上方）：

- **T 出生** 在南侧；**长 A**（东侧长廊）通向 **A 点**（东北）。
- **B 洞**（西侧通道）从 T 出生通向 **B 点**（西侧）。
- **中门**（两扇门）连接 T 方的下中路与 **中路**；中路向西经 **猫道** 进入 B 点，向北经 **短 A** 通向 A 点与 CT 出生。
- **CT 出生** 经 **上 B 洞** 直达 B 点。

这是对 Dust2 核心区域的手工近似，并非逐像素复刻。`tests/map.test.ts` 验证了所有区域互相连通、中门可穿过、关键点可行走。

## 架构

```
src/game/            纯 TypeScript 逻辑（不依赖 three / React，可在 Node 中测试）
  config.ts          全局常量（尺度、物理、回合规则）
  map/               布局字符矩阵 → 合并矩形 / 碰撞体 / 门
  physics/           AABB 碰撞、分轴滑动、台阶、重力、射线
  nav/               2m 网格 A* 寻路 + 视线平滑
  weapons/           武器数据表（伤害、射速、扩散、后坐力、弹匣、开镜）
  entities/          角色状态（护甲减伤、换弹、武器槽）
  combat/            命中分区（头/胸/腹/臂/腿）、视线、刀
  ai/brain.ts        AI 有限状态机：engage / search / objective / action / hold
  round/             C4 状态机、回合胜负判定、比赛结算
  world/gameWorld.ts 逻辑世界：固定步长 step()，产出事件与 HUD 快照
  runtime/           requestAnimationFrame 控制器（累加器固定步长）、键鼠输入
  render/            three.js：程序化人形角色、武器模型、地图网格、第一人称手臂、特效
  audio/sound.ts     Web Audio 程序化合成（枪声按武器区分、脚步、换弹、C4 等）
src/store/           外部状态仓库（HUD 快照 20Hz 推送）
src/ui/              React：菜单、HUD 叠层、小地图（canvas）、暂停 / 结束界面
tests/               逻辑层测试（node --test）
```

**数据同步**：3D 循环不直接写 React 状态。逻辑按 `FIXED_DT = 1/120s` 固定步长推进；渲染器和音效读取逻辑产生的事件；约 20Hz 生成只读 HUD 快照写入外部 store，React 通过 `useSyncExternalStore` 只订阅所需字段。指针未锁定（按 ESC）时模拟暂停。

**AI**：每 1/30s 决策一次，转向在每个物理 tick 平滑执行。感知包括距离、视野锥（65°）和墙体视线遮挡；听到 0.8s 内敌方枪声会前往搜索；T 方按 A/B 分组推进，持包者到点后下包，掉包后就近者捡起；CT 方两人赶去拆包，其余守点。

## 已实现的规则

- 武器：Glock-18、USP-S、沙漠之鹰、AK-47、M4A4、AWP（右键开镜，移动减速，单发 115 伤害）、战术刀（斩击 / 突刺）。伤害梯度：手枪 < 沙鹰 < 步枪；AWP 单发致命。
- 命中：头部伤害为身体（胸口）的 2 倍；护甲吸收 50% 伤害并被消耗。
- 手枪局：第一回合全员只带默认手枪，护甲 50；之后按所选武器全员满护甲 100。
- C4：回合开始随机分配给一名 T；持包者阵亡后掉落可被 T 捡起；安放后 40s 爆炸（范围 22m 内全部击杀）；拆除需 5s。
- 回合：CT 全灭 → T 胜；T 全灭且未下包 → CT 胜；爆炸 → T 胜；拆除 → CT 胜；115s 未下包 → CT 胜。先到 8 分者赢得比赛。
- 阵亡后可观察或接管存活队友。
- 小地图：自己、队友、被看见的敌人（队友视野内）、C4 位置。

## 已知局限

- 仅单机，没有网络对战与经济系统（没有购买菜单，装备由开局选择决定）。
- 地图为单层平面：猫道和中门为同一高度的通路，没有斜坡与高低差。
- 角色动画为程序化摆动，没有蹲下、跳跃姿态与骨骼动画。
- AI 的协同较弱：没有烟雾、闪光弹与道具；T 方一波推进失败时偶尔会整体被击破而无法下包（测试以 8 回合窗口断言）。
- 声音为程序化合成，音色以"可区分"为目标，不追求真实录音的质感。
