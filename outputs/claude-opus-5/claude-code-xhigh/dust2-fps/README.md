# Dust2 — 浏览器 3D 第一人称射击原型

React 18 + TypeScript + three.js 从零实现的 5v5 战术射击原型，复刻 de_dust2 核心区域。

**零外部资产**：没有任何 3D 模型、贴图、音频文件。地图 / 角色 / 武器全部在代码里用几何体
procedural 生成，贴图用 Canvas 2D 现画，声音用 Web Audio 现场合成。第三方依赖只有
`three` / `react` / `react-dom`——寻路、状态机、物理、渲染循环、后坐力模型都是自己实现的。

```bash
npm install
npm run dev      # 打开 http://localhost:5173
```

> 依赖里 `three` 与 `@types/three` 是成对锁在 `^0.170.0` 的（这个组合两边都有对应发布）。
> 代码只用了 r152 之后长期稳定的 API（`outputColorSpace` / `SRGBColorSpace` / 物理正确灯光 /
> `MeshLambertMaterial` / 自定义 `ShaderMaterial` 粒子），想升到更新的 r18x 直接改版本号即可，
> 记得两个包一起改。

## 已实现的内容

### 1. 地图

用「区域 + 通道」声明式描述，墙体沿区域周长自动生成并在通道处开洞，
**所以"看得见能不能走"和"墙长什么样"永远来自同一份数据**，不会出现看着通、走不过去的情况。
高差处自动生成台阶。

包含并按 Dust2 实际走位连通：**T 出生点、CT 出生点、A 大(长廊)、A 点、中门（含可穿过的对开门体）、
猫道、A 小道、B 洞（上下两层）、B 点、B 门、CT 中路、深坑、长廊大门**。
共 22 个区域 / 26 条通道 / 40 个掩体 → 编译出 258 个带碰撞的 AABB，约 124m × 128m。

所有墙体和箱子都有碰撞，玩家与 AI 共用同一套物理，谁都穿不过去。

### 2. 角色

程序化人形骨架（`src/render/character.ts`），**独立的头 / 躯干 / 双臂（大臂+小臂+手）/
双腿（大腿+小腿+脚）**，每侧 20+ 个部件，带层级骨骼：

```
root(yaw) → hips → spine → 胸腔/背心/脖子
                     ├ headPivot  → 头 / 面罩 / 头盔
                     ├ shoulderL/R → elbow → forearm → glove
                     └ weaponMount → 武器模型（枪跟着躯干和视角走）
            ├ legL/R → knee → shin → boot
```

动画全部程序化：走路摆腿 + 膝盖只向后弯、呼吸起伏、瞄准俯仰带动脊柱和头、蹲下压重心、
阵亡向后倒地。CT 是深蓝制服 + 头盔护目镜，T 是土黄外套 + 橙红头巾，一眼可辨。

### 3. 武器系统

`src/game/weapons.ts` 是纯数据表，连模型都是数据（`parts` 描述由哪些盒子拼成，
第一人称和第三人称模型共用同一份）。加新枪只需加一条数据。

| 武器 | 伤害 | 射速 | 弹匣 | 特点 |
| --- | --- | --- | --- | --- |
| AK-47 | 40 | 600 | 30 | 后坐力剧烈：抬枪快、横向蛇形摆幅大、扩散涨得快 |
| M4A4 | 33 | 666 | 30 | 后坐力低、射速高，好压枪 |
| AWP | 115 | 41 | 5 | 一枪致命（满甲也是），右键开镜（FOV 90→22 + 2D 镜面遮罩），开镜移速 2.0 m/s |
| 沙漠之鹰 | 32 | 267 | 7 | 手枪里最强、弹匣最小 |
| USP-S | 28 | 353 | 12 | CT 默认，消音枪声明显更轻 |
| Glock-18 | 25 | 400 | 20 | T 默认 |
| 战术刀 | 55 | — | — | 背刺 3.3 倍，移速最快 |

**精度模型**：实际弹道 = 视角(含后坐力冲击) + 半角为 `inaccuracy` 的随机锥；
`inaccuracy = 基础 + 连发累计扩散 + 移动惩罚 + 空中惩罚`，蹲下打七折。
后坐力冲击直接作用在**视角**上，准星会跟着往上飘、子弹永远打在准星处——所以需要往下压鼠标，
也就是压枪。停火 0.35s 后弹道计数复位。

**命中盒分区**（头/胸/腹/手臂/腿），倍率 `2.0 / 1.0 / 1.15 / 0.65 / 0.55`——
按需求爆头正好是身体的两倍。护甲按武器穿透率减伤、头盔单独保护头部、腿部不吃护甲加成，
另有随距离的伤害衰减。

> 说明：需求要求「沙鹰伤害介于手枪与步枪之间」，所以这里是 32。真实 CS 里沙鹰是 63（比 AK 还高），
> 想要那种手感把 `weapons.ts` 里沙鹰的 `damage` 改成 63 即可，其它沙鹰特征（7 发、慢射速、
> 高单发后坐力）已经具备。

### 4. 手枪局

第一回合固定为手枪局：全员只有默认手枪（T=Glock / CT=USP）+ 刀，无主武器、无护甲。
主菜单里可以勾选「全程手枪局」让每一回合都是这个形态。之后的回合有简单经济
（胜 +3250 / 败 1400~2900 递增 / 击杀 +300 / 下包拆包 +300），按 `B` 购买。

### 5. C4 与回合胜负

- 回合开始 C4 随机交给一名 T；携包者阵亡 → C4 掉在原地 → 其他 T 走过去自动捡起
- **下包**：持包 T 在 A/B 点范围内长按 `E`，3.2 秒完成（按住 E 会自动切到 C4），之后 40 秒倒计时
- **拆包**：CT 站在 C4 旁长按 `E`，7 秒完成
- **结算**：T 清空 CT / C4 爆炸 → T 胜；CT 清空 T（未下包）/ 成功拆包 / 时间耗尽未下包 → CT 胜。
  已下包时 T 全灭不会立刻结束——CT 还得去拆
- 爆炸有 22m 范围伤害
- 阵亡后自动进入观战，`空格` 切换存活队友视角，`F` 接管该队友（原角色交还 AI）

### 6. AI

`src/game/ai.ts`，bot 与玩家共用 `Intent` 结构和物理，AI 只是"帮它按手柄"——
所以 bot 不会穿墙、不会无限子弹，玩家接管 bot 也不需要任何特殊分支。

- **寻路**：从碰撞世界烘焙 166×171 的导航网格（可行走 13.5k 格），A\* + 八邻接 + 禁止斜向切角 +
  贴墙格加代价（走廊道中间而不是蹭墙）+ 拉绳平滑；预计算连通块，不可达时不浪费一次搜索。
  单次寻路约 1.2ms，路径每秒重算，被推开或打完架不会"往回走"
- **视野**：眼睛 → 目标胸/头/腿三条真实射线，被墙挡住就是看不见；FOV ±62°，4m 内全向感知
- **交火**：带误差地转枪（误差随技能与"看到多久"收敛），按技能比例压枪，反应时间取决于
  "发现瞬间准星偏多少"——所以架点预瞄的人会赢冲进来的人；自动点射/连发节奏、队友挡枪时不开火
- **战术**：回合开始分配站位（T 3 人主攻 + 2 人牵制，CT 2A/2B/1 中）；T 先到中途推进位再进点，
  携包者进点下包；防守方一发现敌人或有人倒下就从别处调人换防；下包后 CT 全体去拆、T 回防守包
- **卡住检测**：想走却没动就重新寻路并随机绕行

### 7. HUD

十字准星（缺口实时反映当前散布）、生命/护甲、动态弹药面板（弹匣格子 + 换弹进度条）、
右上角击杀播报（含爆头标记）、回合计时/比分/双方存活人数、下包拆包进度条、
受伤红色边缘、阵亡观战提示、记分板、购买菜单、AWP 2D 镜面遮罩。

**小地图**：常驻显示 Dust2 俯视轮廓（区域 + 掩体 + A/B 点框），实时标出自己（带视野扇形）、
队友、**本队当前看得见的**敌人，以及 C4 的位置（已安放时按倒计时节奏闪烁）。

### 8. 声音

`src/audio/audio.ts` 全程序化合成。枪声配方 = 瞬态咔哒 + 低频胸腔正弦 + 滤波白噪声爆音，
每把枪的滤波频率/衰减/基音不同：AK 闷而沉、M4 脆而快、AWP 一声长尾巨响、手枪短促、USP 明显更轻。
另有换弹（弹匣脱出/插入/拉机柄三段）、脚步（按地面材质换滤波）、落地、AWP 开镜、
命中反馈（爆头音更亮）、击杀提示、C4 安放/拆除/滴滴/爆炸、回合开始与胜负音。

还挂了一个**程序化生成的脉冲响应做混响**，让枪声在地图里有回荡感；其他角色的声音走
`PannerNode` 做 3D 定位并跟随镜头朝向，自己的声音直连保证清晰。

### 三条时间线怎么同步

这是本项目最核心的架构问题，答案是**单向数据流 + 三种不同的更新频率**：

```
rAF 循环（可变帧率，通常 60~144Hz）
  ├─ 1. 读输入 → 直接写玩家的 yaw/pitch（零延迟手感）与 Intent
  ├─ 2. engine.step(dtReal)
  │        └─ 内部按固定 1/64s 累加器跑 fixedUpdate：AI → 物理 → 武器 → 炸弹 → 判负
  │           （固定步长保证物理和 AI 完全确定性，掉帧最多补 5 步防止雪崩）
  ├─ 3. events = engine.drainEvents()   ← 一次取走，分发给渲染与音频两个消费者
  ├─ 4. renderer.sync(engine, dt, events)
  │        └─ 用 prevPos/pos + alpha 插值绘制，所以画面平滑与物理频率解耦
  └─ 5. renderer.render()

React（20Hz）
  └─ useSyncExternalStore(engine.subscribe, engine.getSnapshot)
       引擎在关键事件（击杀/回合切换/购买）立刻 notify，其余按 20Hz 推快照。
       快照带缓存，同一版本返回同一个对象引用（useSyncExternalStore 的硬性要求）。

小地图 / 准星（自己开 rAF）
  └─ 直接读引擎状态画 canvas，不走 React——否则 60Hz setState 会把 React 拖垮
```

关键约束：**模拟层永远不知道渲染层和 React 的存在**（有静态检查强制 `src/game`、`src/map`、
`src/core`、`src/audio` 不得 import three）。这既是干净的分层，也是下面那套测试能成立的前提。

## 自检

因为模拟核心是不依赖 three 的纯 TypeScript，可以在 Node 里直接跑（Node 22 原生支持 TS 类型擦除），
**不装依赖也能跑全部自检**：

```bash
npm test                # 跑下面全部 8 项
npm run test:map        # 地图数据体检
npm run test:nav        # 导航 + 射线
npm run test:sim        # 整局无渲染模拟
npm run test:render     # 渲染层冒烟测试
npm run test:balance    # 平衡性批量评估
npm run typecheck       # tsc --noEmit（需要先 npm install）
```

| 检查 | 内容 |
| --- | --- |
| `importcheck` | 每条相对 import 的文件与符号是否存在、类型是否用了 `import type`、模拟核心是否偷偷 import 了 three |
| `tsxcheck` | JSX 标签配对（能区分 `<div>` 和泛型 `useState<Foo>`）、括号平衡、组件是否有定义、Hook 是否在条件里、监听/rAF 是否有清理 |
| `mapcheck` | 区域重叠、通道是否真的相邻、开口宽度是否够人过、区域图连通性、出生点/战术点/下包点是否被卡住、掩体是否堵住通道 |
| `navcheck` | 16 个关键点位两两可达（240 条路线全过）、平滑后每段都真的能走、**网格 DDA 射线与暴力射线逐条对比**、射线性能 |
| `rulescheck` | 把需求里的规则逐条断言：手枪局形态、爆头两倍、护甲/头盔、武器手感梯度、C4 全流程（点外不能下包、下包 3.2s、拆包 7s）、四种结算方式、观战接管、5v5 编制 |
| `simtest` | 10 个 bot 打完整回合，统计击杀/下包/拆包，并检查有没有人跑出地图、卡进几何体、原地打转 |
| `rendercheck` | 用 three 与 DOM 的替身把渲染层真跑起来：贴图生成、地图合批的顶点属性一致性、人形骨架层级与部件数、全部武器模型、特效池、GameRenderer 跑 300 帧（NaN 位置/旋转会直接抛错）、阵亡观战与接管时的渲染 |
| `balance` | 批量跑几十个回合，确认双方胜率、下包率、回合时长都在合理区间 |

一次典型的输出：

```
网格 166 x 171 = 28386 格，可行走 13556 格 (47.8%)，烘焙耗时 84ms
寻路 240 次，平均 1.24ms/次
射线一致性: 4000 条中 0 条不一致
射线性能: 20000 条耗时 26ms (1.3µs/条)

T 胜率 52.8%  (T 19 : 17 CT)
下包率 30.6%，平均回合时长 57.3s，场均击杀 7.0
```

`tools/navdebug.ts` 可以把导航网格按 ASCII 打出来，排查"某块区域走不通"很方便：

```bash
node tools/navdebug.ts mid      # 中门附近的可行走格子
node tools/navdebug.ts ctmid    # 中路→CT中路 台阶的高度
```

## 几个实现细节

**为什么台阶踏面是 0.8m**：导航网格边长 0.75m，踏面必须比它宽，否则会有台阶落不到任何一行格心上，
采样出来的落差就会是两级（超过抬脚高度），AI 会以为能走结果卡在楼梯口。同理，网格判定"站得下"
是从 `地面 + 抬脚高度` 开始算的，必须和 `physics.ts` 的上台阶逻辑完全一致。

**为什么队友会挡子弹**：子弹会被队友挡住但不造成伤害，AI 因此需要检查射线上有没有队友。
这让站位有战术意义，又不会出现友伤劝退。

**为什么架点的人赢**：bot 记录"发现敌人那一瞬间准星偏了多少"，偏得少反应就快。
守方预瞄门口天然占优，攻方必须靠人数和分兵——这也是把 bot 对战胜率从 90% : 10%
调到 ~53% : 47% 的关键一环。

## 已知取舍

- 没有烟雾弹/闪光弹/手雷，所以进攻方缺少真实 CS 里破点的工具，平衡靠人数分配与 AI 参数补偿
- 地图是 Dust2 核心区域的**空间尺度合理的复刻**，不是逐单位还原（约 1.4 倍真实尺度），
  长廊、中门、猫道、B 洞的相对位置与连通关系忠实于原图
- 阵营切换、真实经济的强制购买规则、观战自由视角（目前是队友第一人称）等未实现
- `main.tsx` 没有开 `StrictMode`：开发模式下它会把 effect 跑两遍，导致 WebGL 上下文与游戏循环被创建两次
